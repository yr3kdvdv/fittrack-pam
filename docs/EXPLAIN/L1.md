## E1. Переменные и null safety — `e1_null_safety.dart`

```dart
int parseOrDefault(String? input, int fallback)
```

**На входе:** `input` — строка или `null`; `fallback` — число, которое вернуть,
если строку нельзя разобрать как целое число.

**Алгоритм:**
1. Если `input == null` — сразу вернуть `fallback`.
2. Иначе попробовать разобрать строку через `int.tryParse`.
3. Если разбор не удался (`tryParse` вернул `null`) — вернуть `fallback`.

**Возвращает:** `int` — разобранное число или `fallback`. Никогда не `null`
и никогда не бросает исключение.

**Разбор ключевых строк:**
- `String? input` — `?` после типа разрешает передать `null`. Без него вызов
  `parseOrDefault(null, 7)` не скомпилируется.
- `if (input == null) return fallback;` — после этой строки компилятор знает, что
  `input` уже не `null`, и считает его типом `String` (*type promotion*). Поэтому
  оператор `!` не нужен (ограничение ТЗ).
- `int.tryParse(input)` — возвращает `int?`: число или `null` для `'abc'` и `'7.5'`.
  В отличие от `int.parse`, исключение не бросает.
- `?? fallback` — если слева `null`, берётся значение справа.

**Альтернатива:** `int.tryParse(input ?? '') ?? fallback` — одна строка, потому что
`tryParse('')` тоже даёт `null`. Выбран вариант с `if`: его проще объяснить по шагам.

**Результат запуска:**
```
parseOrDefault('42', 0) → 42
parseOrDefault('abc', 0) → 0
parseOrDefault(null, 7) → 7
parseOrDefault('7.5', -1) → -1
```
Проверка ограничения: `grep -n '!' dart_exercises/e1_null_safety.dart` ничего не находит.

**Вопросы преподавателя:**
1. *Почему после `if` не нужен `!`?* — Flow analysis: при `null` функция уже вышла,
   поэтому ниже компилятор считает `input` типом `String`. Надёжнее всего это работает
   для локальных переменных и параметров, как здесь. С Dart 3.2 так же сужаются
   подходящие приватные `final`-поля (имя с `_`). Публичное или изменяемое поле и
   getter могут не сузиться: компилятор не может доказать, что значение не
   изменится между проверкой и использованием. Тогда значение копируют в локальную
   переменную. Причины перечислены в https://dart.dev/tools/non-promotion-reasons.
2. *Почему `'7.5'` даёт `-1`?* — `int.tryParse` разбирает только целые числа, для
   `'7.5'` он возвращает `null`, и `??` подставляет `fallback`. Дробные числа
   разбирает `double.tryParse`.
3. *Почему не `int.parse` в `try/catch`?* — `int.parse` бросает `FormatException`.
   Неверный ввод — обычная ситуация, а не ошибка, поэтому `tryParse` + `??` проще
   и дешевле исключений. ТЗ прямо требует `tryParse`.

## E2. Коллекции и функциональные методы — `e2_collections.dart`

```dart
double promotedAverage(List<int> grades)
```

**На входе:** список оценок (целые числа 1–10).

**Алгоритм:**
1. Отфильтровать проходные оценки (`>= 5`) через `where`.
2. Если проходных нет — вернуть `0.0`.
3. Сложить их через `reduce`.
4. Разделить сумму на количество.

**Возвращает:** `double` — среднее проходных оценок или `0.0`.

**Разбор ключевых строк:**
- `grades.where((g) => g >= 5).toList()` — `(g) => g >= 5` — анонимная функция,
  которая для каждой оценки отвечает `true`/`false`. `where` лениво описывает
  фильтр, а `toList()` выполняет его один раз и сохраняет результат: дальше мы
  обращаемся к нему трижды (`isEmpty`, `reduce`, `length`).
- `if (passed.isEmpty) return 0.0;` — требование ТЗ. Кроме того, `reduce` на пустом
  списке бросает `StateError`, поэтому проверка стоит до него.
- `passed.reduce((a, b) => a + b)` — складывает элементы по очереди:
  `9 + 7 = 16`, `16 + 10 = 26`, `26 + 5 = 31`.
- `sum / passed.length` — оператор `/` в Dart всегда даёт `double`: `31 / 4 = 7.75`.

**Альтернатива:** `fold(0, (sum, g) => sum + g)` — с начальным значением не падает на
пустом списке, но проверка `isEmpty` всё равно нужна, иначе `0 / 0 = NaN`.
`map` не понадобился: оценки только фильтруются и суммируются.

**Результат запуска:**
```
promotedAverage([9, 4, 7, 10, 3, 5]) → 7.75
promotedAverage([10, 10, 9]) → 9.666666666666666
promotedAverage([3, 4, 2]) → 0.0
```
Проверка ограничения: `grep -nwE 'for|while' dart_exercises/e2_collections.dart`
ничего не находит.

**Вопросы преподавателя:**
1. *Чем `reduce` отличается от `fold`?* — `reduce` берёт первый элемент как начальное
   значение и падает на пустой коллекции; тип результата совпадает с типом элементов.
   `fold` получает начальное значение явно, работает на пустой коллекции и может
   вернуть другой тип.
2. *Что такое ленивый `Iterable`?* — `where` и `map` не создают новый список, а
   описывают вычисление, которое выполняется при каждом обходе. `toList()` выполняет
   его сразу и один раз.
3. *Чем `/` отличается от `~/`?* — `/` всегда возвращает `double` (`7 / 2 = 3.5`),
   `~/` — целочисленное деление, возвращает `int` (`7 ~/ 2 = 3`).

## E3. Именованные и необязательные параметры — `e3_functions.dart`

```dart
String formatPrice(double amount, {String currency = 'MDL', int decimals = 2})
```

**На входе:** `amount` — сумма (позиционный, обязательный параметр); `currency` —
валюта (именованный, по умолчанию `'MDL'`); `decimals` — число знаков после точки
(именованный, по умолчанию `2`).

**Алгоритм:**
1. Превратить сумму в строку с `decimals` знаками после точки (`toStringAsFixed`),
   с округлением.
2. Через пробел дописать валюту.

**Возвращает:** `String` вида `"12.50 MDL"`.

**Разбор ключевых строк:**
- `{String currency = 'MDL', int decimals = 2}` — фигурные скобки делают параметры
  именованными: при вызове пишется имя (`currency: 'EUR'`), порядок не важен, и
  параметр можно пропустить — тогда берётся значение после `=`.
- `amount.toStringAsFixed(decimals)` — ровно `decimals` знаков после точки, с
  округлением: `99.999 → "100.00"`, `7.5` с `decimals: 1` → `"7.5"`.
- `'${...} $currency'` — интерполяция: `${выражение}` для выражения, `$имя` для
  простой переменной.

**Альтернатива:** необязательные *позиционные* параметры `[String currency = 'MDL',
int decimals = 2]`. Тогда нельзя передать `decimals`, не передав `currency`, и вызов
`formatPrice(7.5, 'USD', 1)` хуже читается. ТЗ требует именованные.

**Результат запуска:**
```
formatPrice(12.5) → "12.50 MDL"
formatPrice(12.5, currency: 'MDL') → "12.50 MDL"
formatPrice(99.999, currency: 'EUR') → "100.00 EUR"
formatPrice(7.5, currency: 'USD', decimals: 1) → "7.5 USD"
```
Кавычки вокруг результата печатает `main`, чтобы вывод совпадал с записью в ТЗ.

**Вопросы преподавателя:**
1. *Чем именованный параметр `{}` отличается от необязательного позиционного `[]`?* —
   Именованный передаётся по имени и в любом порядке. Позиционный передаётся по
   месту, и пропускать можно только параметры с конца списка.
2. *Что, если у именованного параметра нет значения по умолчанию?* — Тогда он либо
   nullable (`String? currency`, по умолчанию `null`), либо помечается `required`
   и становится обязательным.
3. *Почему деньги в `double` — плохо в реальном проекте?* — `double` не хранит
   точно многие десятичные дроби (`0.1 + 0.2 != 0.3`). Суммы хранят в целых
   копейках (`int`) или в десятичном типе. Здесь `double` задан сигнатурой ТЗ.

## E4. Классы — `e4_classes.dart`

```dart
class Student {
  final String name;
  final String group;
  // Student(...), Student.guest(), toString, ==, hashCode
}
```

**На входе:** конструктор принимает `name` и `group`; `Student.guest()` —
без аргументов.

**Алгоритм:**
1. Основной конструктор записывает аргументы в поля.
2. `Student.guest()` перенаправляет в основной конструктор со значениями
   `'Guest'` и `'—'`.
3. `toString` собирает строку `Student(name, group)`.
4. `==` сравнивает тип и оба поля; `hashCode` считается из тех же полей.

**Возвращает:** объекты `Student`; `toString` → `String`, `==` → `bool`,
`hashCode` → `int`.

**Разбор ключевых строк:**
- `Student(this.name, this.group);` — `this.name` в параметрах сразу записывает
  аргумент в поле.
- `Student.guest() : this('Guest', '—');` — безымянный конструктор у класса может
  быть только один, остальные получают имена. `: this(...)` вызывает основной.
- `@override String toString()` — `print` вызывает именно этот метод. Без
  переопределения печаталось бы `Instance of 'Student'`.
- `bool operator ==(Object other) => other is Student && ...` — по умолчанию `==`
  сравнивает ссылки (один ли это объект в памяти). Мы сравниваем содержимое.
  После `other is Student` Dart считает `other` студентом и даёт доступ к его полям.
- `int get hashCode => Object.hash(name, group);` — у равных объектов хэш обязан
  совпадать, поэтому он считается из тех же полей, что и `==`.

**Альтернатива:** `Student.guest() : name = 'Guest', group = '—';` (список
инициализации) или `factory Student.guest()`. Результат тот же; перенаправление
держит создание объекта в одном месте.

**Результат запуска:**
```
Student(Ana Rusu, TI-231)
Student(Guest, —)
Student('Ana Rusu', 'TI-231') == Student('Ana Rusu', 'TI-231') → true
{Student('Ana Rusu', 'TI-231'), Student('Ana Rusu', 'TI-231')}.length → 1
```
Проверка `hashCode`: во временной копии класса без `hashCode` оператор `==` давал
`true`, а `Set` содержал 2 элемента. С `hashCode` в `Set` один элемент.

**Вопросы преподавателя:**
1. *Почему `==` и `hashCode` переопределяют вместе?* — `Set` и `Map` сначала
   сравнивают `hashCode` и только при совпадении вызывают `==`. Если равные объекты
   имеют разный хэш, в `Set` появятся дубликаты, а `Map` не найдёт ключ.
2. *Почему параметр `==` имеет тип `Object`, а не `Student`?* — Так `==` объявлен
   в базовом классе `Object`, а при переопределении тип параметра сужать нельзя.
   Поэтому тип проверяется внутри через `is`.
3. *Почему `Object.hash`, а не `name.hashCode ^ group.hashCode`?* — У `^` результат
   не зависит от порядка: `Student('A', 'B')` и `Student('B', 'A')` получат
   одинаковый хэш. `Object.hash` порядок учитывает.

## E5. Mixin — `e5_mixin.dart`

```dart
mixin Loggable { void log(String msg) }
class CartService with Loggable { void addItem(String item) }
class AuthService with Loggable { void login(String username) }
```

**На входе:** `log` получает текст сообщения; `addItem` — название товара;
`login` — имя пользователя.

**Алгоритм:**
1. `log` печатает `[ИмяКласса] сообщение`, имя берётся из `runtimeType`.
2. `addItem` и `login` формируют свой текст и вызывают `log`.

**Возвращает:** ничего (`void`), результат — строки в консоли.

**Разбор ключевых строк:**
- `mixin Loggable` — набор методов, который можно подключить к классу. Создать
  объект mixin-а нельзя.
- `class CartService with Loggable` — после `with` метод `log` становится частью
  класса, поэтому в `addItem` его можно просто вызвать.
- `print('[$runtimeType] $msg')` — `runtimeType` — настоящий класс объекта во время
  выполнения. Код один, а печатается `CartService` или `AuthService`.
- `=>` — короткая запись функции из одного выражения.

**Альтернатива:** базовый класс и `extends`. Но родитель у класса может быть только
один, а mixin-ов — сколько угодно (`with A, B`), поэтому логирование не «занимает»
место родителя.

**Результат запуска:**
```
[CartService] товар добавлен: Paracetamol
[AuthService] пользователь вошёл: ana.rusu
```

**Вопросы преподавателя:**
1. *Чем mixin отличается от наследования?* — `extends` — один родитель, отношение
   «является». `with` подключает готовое поведение, mixin-ов может быть несколько.
2. *Чем mixin отличается от интерфейса (`implements`)?* — Интерфейс задаёт только
   сигнатуры, и каждый класс пишет реализацию сам. Mixin приносит готовую реализацию.
3. *Что, если у двух mixin-ов одинаковый метод?* — Побеждает указанный последним
   в `with A, B`: mixin-ы накладываются слоями слева направо.

## E6. Асинхронное программирование — `e6_async.dart`

```dart
Future<String> fetchProfile(String username)
```

**На входе:** имя пользователя.

**Алгоритм:**
1. `main` печатает «Загружается профиль…».
2. `fetchProfile` ждёт 2 секунды (`Future.delayed`) и возвращает строку профиля.
3. `main` ждёт результат через `await`, печатает профиль, затем «Готово.».

**Возвращает:** `Future<String>` — «обещание» строки, которая будет готова через
2 секунды.

**Разбор ключевых строк:**
- `Future<String> fetchProfile(...) async` — `async` разрешает `await` внутри и
  сам заворачивает `return` в `Future`.
- `await Future.delayed(const Duration(seconds: 2));` — ждём 2 секунды, не блокируя
  программу: event loop в это время свободен для другой работы.
- `Future<void> main() async` — `main` тоже `async`, иначе в ней нельзя `await`.
- `final profile = await fetchProfile('ana.rusu');` — `main` приостанавливается,
  пока профиль не готов. Поэтому «Готово.» гарантированно печатается после профиля.

**Альтернатива:** цепочка `fetchProfile(...).then((p) { ... })` — то же поведение,
но при нескольких шагах растёт вложенность. Блокирующий `sleep` из `dart:io`
остановил бы весь поток, а во Flutter — заморозил бы интерфейс.

**Результат запуска** (время прихода строки, считая от первой):
```
+0.00s  Загружается профиль пользователя ana.rusu...
+2.01s  Профиль: ana.rusu, группа TI-231, решено упражнений: 42
+2.01s  Готово.
```

**Вопросы преподавателя:**
1. *Что будет, если убрать `await` только из строки
   `final profile = await fetchProfile('ana.rusu');`?* — `fetchProfile` сразу вернёт
   незавершённый `Future`, и `final profile` получит тип `Future<String>` (объявлять
   тип вручную не нужно, `final` выведет его сам). `main` не ждёт: `print(profile)`
   печатает представление самого объекта `Future`, а не текст профиля, и сразу за
   ним идёт «Готово.». Через 2 секунды `fetchProfile` завершит `Future` строкой, но
   эта строка никуда не напечатается: внутри `fetchProfile` нет `print`, а результат
   никто не читает.

   Как всё-таки получить строку:
   - `fetchProfile('ana.rusu').then(print);` — `then` регистрирует функцию, которая
     вызовется со строкой, когда `Future` завершится. `main` при этом не ждёт, поэтому
     «Готово.», напечатанное следующей строкой, появится раньше профиля.
   - `final profile = await fetchProfile('ana.rusu');` (как в коде) или, если
     `profile` уже `Future<String>`, `print(await profile);` — `await` приостанавливает
     `main` до готовности результата и отдаёт саму строку (`String`), поэтому профиль
     печатается до «Готово.».
2. *Dart многопоточный?* — Код выполняется в одном потоке (изоляте). Асинхронность —
   не параллельность, а переключение между задачами, пока одна ждёт. Для тяжёлых
   вычислений есть отдельные изоляты (`Isolate.run`).
3. *Почему `main` возвращает `Future<void>`?* — Функция с `async` всегда возвращает
   `Future`. `void main() async` тоже компилируется, но `Future<void>` точнее
   описывает тип.

## Ответы на контрольные вопросы из ТЗ

### Что делает `??` и чем он отличается от `?.` и от `!`?

Все три оператора работают с nullable-значениями, но делают разное:

| Оператор | Что делает | Пример | Если значение `null` |
|---|---|---|---|
| `a ?? b` | подставляет значение по умолчанию | `name ?? 'Гость'` | результат — `b` |
| `a?.b` | обращается к члену, только если `a` не `null` | `name?.length` | результат — `null`, без ошибки |
| `a!` | утверждает «здесь точно не `null`», снимает `?` с типа | `name!.length` | ошибка во время выполнения (`TypeError`) |

`??` и `?.` безопасны, `!` перекладывает проверку на программиста. Их часто
комбинируют: `name?.length ?? 0` — длина строки или 0, если строки нет. Есть и
`a ??= b` — присвоить `b`, только если `a` сейчас `null`. В E1 используется `??`,
а `!` не используется: вместо него проверка `if (input == null)` и type promotion.

### В чём разница между `final` и `const`?

- `final` — переменной можно присвоить значение **один раз**, но само значение может
  вычисляться во время выполнения: `final now = DateTime.now();`.
- `const` — значение должно быть известно **при компиляции**: `const pi = 3.14;`.
  `DateTime.now()` в `const` записать нельзя.
- `const`-объекты с одинаковым содержимым — это один и тот же объект в памяти
  (канонизация), поэтому их удобно переиспользовать. Во Flutter виджет — это
  неизменяемое описание (конфигурация) части интерфейса. Если написать
  `const Text('Привет')`, при каждом `build` родителя используется тот же готовый
  экземпляр, а не создаётся новый. Увидев тот же экземпляр, Flutter может не
  перестраивать эту ветку заново, и работы становится меньше. Но `const` не запрещает
  перестроение совсем: `const`-виджет со своим `State` или зависящий от `Theme`,
  `MediaQuery` и других inherited-данных всё равно перестроится, когда они
  изменятся. Источник: https://docs.flutter.dev/perf/best-practices.
- `const` делает неизменяемым и содержимое: в `const list = [1, 2]` нельзя добавить
  элемент. У `final list = [1, 2]` нельзя заменить сам список, но `list.add(3)`
  работает.

В коде: поля `Student` объявлены `final` (задаются в конструкторе, то есть во время
выполнения); в E6 `const Duration(seconds: 2)` — значение известно заранее.

### Что даёт `async`/`await` по сравнению с блокирующими вызовами и с цепочками `then`?

- **Против блокирующих вызовов.** Блокирующий вызов (`sleep`, синхронное чтение
  файла) останавливает поток целиком, и в это время ничего не происходит. Во
  Flutter это «зависший» интерфейс. `await` приостанавливает только текущую функцию,
  а event loop продолжает обрабатывать другие события (отрисовку, нажатия, таймеры).
- **Против `then`.** Поведение то же, `await` — это более удобная запись того же
  `Future`. Код читается сверху вниз как обычный, промежуточные результаты лежат в
  переменных, ошибки ловятся обычным `try/catch` вместо `.catchError`, нет вложенных
  колбэков.

```dart
// then
fetchProfile('ana.rusu').then((p) {
  print(p);
  print('Готово.');
});

// async/await — то же самое
final p = await fetchProfile('ana.rusu');
print(p);
print('Готово.');
```
