# L2 — объяснение реализации

## Этап 1A: создание Flutter-проекта

**Команда** (из корня репозитория):

```sh
flutter create --platforms=android --project-name fittrack app
```

- `app` — каталог пакета внутри существующего Git-репозитория. Вложенный
  `.git` flutter create не создаёт; файлы попадают в общий репозиторий.
- `--project-name fittrack` — имя Dart-пакета (`name:` в pubspec.yaml,
  импорты вида `package:fittrack/...`). Без флага имя взялось бы из каталога
  (`app`), что неинформативно.
- `--platforms=android` — генерируется только каталог android/: целевая
  платформа курса — Android, лишние ios/web/desktop увеличили бы репозиторий.

**Что создано** (отслеживаемые Git файлы):
- `pubspec.yaml`, `pubspec.lock` — описание пакета и зафиксированные версии.
  SDK-ограничение `^3.13.4` выставлено по установленному Dart.
- `analysis_options.yaml` — подключает правила flutter_lints.
- `lib/main.dart` — шаблон-счётчик; будет заменён на этапе темы.
- `test/widget_test.dart` — шаблонный smoke-test счётчика.
- `android/` — Gradle-проект (Kotlin DSL), MainActivity, манифесты, иконки.
- `.gitignore`, `.metadata`, `README.md`.

Не отслеживаются (игнорируются): `.dart_tool/`, `.idea/`, `fittrack.iml`, `build/`.

**Альтернативы.** Создать проект в корне репозитория — смешало бы Flutter-файлы
с dart_exercises и документацией L1. Android Studio wizard — тот же шаблон,
но команду проще воспроизвести и показать в отчёте.

**Вопросы преподавателя**
- *Зачем pubspec.lock в Git?* Это приложение, а не библиотека: lock фиксирует
  версии, чтобы сборка у всех была одинаковой.
- *Что такое `--project-name`?* Имя Dart-пакета; от него зависят импорты
  `package:fittrack/...` и `applicationId com.example.fittrack`.
- *Почему только Android?* Целевая платформа курса; остальные платформы
  можно добавить позже командой `flutter create --platforms=ios .`.
- *Как проверили каркас?* `flutter analyze` — без замечаний, `flutter test` —
  проходит шаблонный тест, `dart format` — изменений нет.

## Этапы 1–9: тема и семь экранов

Каждый этап — отдельный коммит после `dart format`, `flutter analyze` и тестов.
Порядок коммитов: тема → очистка шаблона → вход и оболочка → каталог →
карточка упражнения → дневник → форма сессии → статистика → профиль → тест
маршрута. Полный список: `git log --oneline`.

### Как устроено приложение

- `main.dart` — `FitTrackApp`: `MaterialApp` с темой, стартовый экран — вход.
- `theme.dart` — `ColorScheme.fromSeed(seedColor: Color(0xFF00897B))`.
  Бирюзово-зелёный выбран как цвет спорта и здоровья: энергичный, но спокойный.
  Из одного seed Material 3 строит всю палитру (`primary`, `primaryContainer`,
  `surface…`). Экраны берут цвета только через `Theme.of(context).colorScheme`,
  поэтому смена seed перекрашивает всё приложение (можно показать hot reload).
- `data/mock_data.dart` — модели `Exercise` и `WorkoutSession` с полями из ТЗ
  и зашитые списки. Данные нужны нескольким экранам, поэтому лежат в одном
  месте, а не копируются. `DateTime` не бывает `const`, поэтому сессии — `final`.
- `data/formatters.dart` — «Суббота, 17 октября», «1 ч 15 мин», «12–18 окт.».
  Пакет intl не добавлен: ради четырёх функций зависимость не нужна.
- `screens/` — по файлу на экран; `widgets/` — повторяющиеся части.

### Экраны (в порядке каталога ТЗ)

1. **Вход / регистрация** (`login_screen.dart`) — логотип, два `TextField`
   (e-mail и пароль с `obscureText: true`), `FilledButton` «Войти», `TextButton`
   регистрации. Без `Form` и проверок. «Войти» делает `pushReplacement` на
   оболочку, чтобы «Назад» не возвращал на вход. Всё в `SingleChildScrollView` —
   клавиатура не вызывает overflow.
2. **Каталог упражнений** (`exercises_screen.dart`) — `SearchBar`, ряд
   `FilterChip` по группам мышц, список `ExerciseTile`. Поиск и фильтры только
   визуальные (работать начнут на L4). `CustomScrollView` со sliver-ами:
   поиск, фильтры и список прокручиваются вместе. `SliverList.separated` строит
   только видимые карточки — аналог `ListView.separated`.
3. **Карточка упражнения** (`exercise_detail_screen.dart`) — крупная иконка
   группы мышц вместо фото, название, `Chip` группы, описание и пронумерованные
   шаги техники. Получает `Exercise` через конструктор. Шаг техники — `Row`, где
   текст обёрнут в `Expanded`, иначе длинная строка вызвала бы overflow.
4. **Дневник тренировок** (`workouts_screen.dart`) — `ListView.separated` из
   13 `SessionCard`, сначала новые. FAB «Новая тренировка» открывает форму,
   нажатие на карточку — форму редактирования этой сессии.
5. **Новая / редактируемая сессия** (`workout_edit_screen.dart`) — поля даты,
   длительности (клавиатура цифр, суффикс «мин»), список упражнений с
   `Checkbox`, заметки. Обычные `TextField` без `Form` и `validator`. Значения
   выбранной сессии показаны подсказками (`hintText`, подпись всегда сверху);
   у новой сессии — зашитая демо-дата `mockToday` (18.10.2026), 60 мин и пример
   заметки. Контроллеров нет не потому, что StatelessWidget не может их
   содержать: созданный в `build` контроллер некому освободить (у StatelessWidget нет метода жизненного цикла dispose), а макету без сохранения он не нужен. Текст ввести можно,
   но он не сохраняется. «Сохранить» просто закрывает экран (`Navigator.pop`).
6. **Статистика** (`stats_screen.dart`) — четыре `MetricCard` (13 тренировок,
   12 ч, средняя 55 мин, максимум 3 за неделю) и 6 недель с полосой
   `LinearProgressIndicator`. Итоги зашиты в данных, но тест сверяет их
   с сессиями дневника, так что цифры не расходятся.
7. **Профиль** (`profile_screen.dart`) — аватар с инициалами, e-mail, две
   `MetricCard`, личные данные, настройки (`SwitchListTile` без эффекта),
   «Выйти» → экран входа.

### Переиспользуемые widgets

| Widget | Параметры | Где используется |
|---|---|---|
| `ExerciseTile` | `exercise`, `onTap`, `trailing` | каталог (стрелка, переход), форма (Checkbox) |
| `MuscleGroupAvatar` | `muscleGroup`, `radius` | `ExerciseTile`, карточка упражнения (radius 56) |
| `SessionCard` | `session`, `onTap` | дневник, 13 раз |
| `SectionTitle` | `title`, `icon` | карточка, форма, статистика, профиль |
| `MetricCard`, `MetricPair` | `icon`, `value`, `label`; `left`, `right` | статистика, профиль |

Изменение вида карточки в одном файле меняет её на всех экранах.

### Навигация

Вход → `HomeShell` (`NavigationBar`, 4 вкладки) → `Navigator.push` на карточку
упражнения и форму. `HomeShell` — единственный `StatefulWidget`: `setState`
меняет только индекс вкладки, содержимое экранов не меняется. Это допустимое
исключение из ТЗ L2. На L3 навигацию заменит go_router.

### Проверки

Тесты в `app/test`: данные (≥8 упражнений, ≥8 сессий, ссылки на каталог,
порядок дат, статистика = сессии), каждый экран, маршрут по всем 7 экранам с
возвратом, узкий экран 320×640 + шрифт 1.3 + клавиатура 280 px для каждого
экрана и оболочки. Приложение проверено на Android-эмуляторе; скриншоты сохранены в docs/L2/evidence.

### Почему так, а не иначе

- Иконки вместо фото: ТЗ допускает Icon-заглушку, а 2–3 картинки на 10
  упражнений выглядели бы неравномерно (решение — docs/decisions/L2-static-ui.md).
- Техника — отдельная карта по id: модель `Exercise` остаётся как в backend.
- Недельные итоги зашиты в данных; экран статистики только форматирует их,
  считает среднюю длительность и длину полос. Вычисления над статическими
  данными допустимы на L2; L4 — это изменяемое состояние (новая тренировка
  должна сразу менять итоги).

### Вопросы преподавателя (подготовленные ответы по коду)

- *Stateless или Stateful, почему на L2 всё Stateless?* Данные экранов не
  меняются во время работы. Чтобы работал фильтр, нужно хранить выбранную
  группу: StatefulWidget с `setState` или (на L4) state management.
- *Жёлто-чёрные полосы у края Row?* Overflow: детям не хватило ширины. Лечится
  `Expanded`/`Flexible` (см. шаг техники, дата в `SessionCard`) или прокруткой.
- *Как цвет seed доходит до Card?* `MaterialApp(theme:)` кладёт тему в дерево;
  `Theme.of(context)` находит её у ближайшего предка; Card по умолчанию берёт
  цвета из `colorScheme`.
- *Зачем ListView.builder/.separated?* Строит только видимые элементы, а не все
  сразу; разделители задаются одним `separatorBuilder`.
- *Scaffold и MaterialApp?* Scaffold даёт экрану AppBar, body, FAB, учёт
  клавиатуры; MaterialApp — тему, Navigator, локализацию Material. Без них нет
  стилей Material и переходов.
- *Покажите reusable widget.* `ExerciseTile`: параметры `exercise`, `onTap`,
  `trailing`; в каталоге — стрелка и переход, в форме — Checkbox.
- *Почему форма не сохраняет?* По ТЗ L2 это макет; валидация — L3, данные — L4.
