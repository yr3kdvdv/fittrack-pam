# L3 — объяснение реализации

## Этап 1: установка go_router

```sh
flutter pub add go_router
```

Команда сама выбрала совместимую версию (`go_router: ^18.1.1`) и обновила
pubspec.yaml и pubspec.lock.

## Этап 2: карта маршрутов и адресные переходы

**Что добавлено**
- `lib/router.dart` — функция `createRouter()` с картой маршрутов и
  единственный экземпляр `appRouter` для приложения.
- `lib/main.dart` — `MaterialApp.router(routerConfig: ...)` вместо `home:`.
- `lib/screens/not_found_screen.dart` — сообщение «не найдено» для неизвестного id.
- `HomeShell` стал StatelessWidget: выбранная вкладка вычисляется из адреса.

**Карта маршрутов**

| Адрес | Экран | Внутри оболочки |
|---|---|---|
| `/login` | LoginScreen (стартовый) | нет |
| `/exercises` | ExercisesScreen | да |
| `/exercises/:id` | ExerciseDetailScreen | да |
| `/workouts` | WorkoutsScreen | да |
| `/workouts/new` | WorkoutEditScreen (новая) | да |
| `/workouts/:id/edit` | WorkoutEditScreen (редактирование) | да |
| `/stats` | StatsScreen | да |
| `/profile` | ProfileScreen | да |

Детали и форма — вложенные маршруты своих вкладок, поэтому при прямом открытии
`/exercises/ex-01` под деталями уже есть каталог и кнопка «Назад» работает.

**Передаётся только id.** В адрес попадает строковый id (`ex-01`, `ws-12`),
экран сам ищет объект в mock-данных через `where(...).firstOrNull`. Если id
нет, показывается NotFoundScreen с кнопкой возврата к списку — без исключения.
Модель через `extra` не передаётся: адрес остаётся полным описанием экрана, его
можно открыть напрямую, и он не ломается при перезапуске.

**push, pop и go**
- `context.push` — детали упражнения и форма тренировки: экран кладётся поверх
  списка, `context.pop` (или стрелка «Назад») возвращает к нему.
- `context.go` — вход, выход и переключение вкладок: стек заменяется целиком.
  После входа «Назад» не вернёт на экран входа, после выхода — в приложение.

**Оболочка.** Пока это простой `ShellRoute`: нижняя панель общая для всех
вкладок и видна в деталях и форме. Переключение вкладки через `go` сбрасывает
её стек. Независимые стеки вкладок (`StatefulShellRoute`) — следующий этап.

**Почему роутер создаётся один раз.** `appRouter` — переменная верхнего уровня,
а не объект внутри `build`. Иначе каждая перестройка `FitTrackApp` создавала бы
новый роутер и сбрасывала текущий экран на `/login`. Тесты получают собственный
роутер из той же `createRouter()`, чтобы не зависеть друг от друга.

**Альтернативы.** Navigator 1.0 (`Navigator.push` + `MaterialPageRoute`) — был в
L2, но у экранов нет адресов и их нельзя открыть напрямую. Именованные маршруты
`MaterialApp.routes` не поддерживают параметры пути вроде `:id` без ручного разбора.

**Вопросы преподавателя**
- *Почему `/workouts/new` не воспринимается как id?* Редактирование —
  `/workouts/:id/edit`, в нём обязателен сегмент `edit`. Адрес `/workouts/new`
  совпадает только с маршрутом `new`.
- *Что будет при `/exercises/abc`?* Экран не найдёт упражнение и покажет
  «Упражнение не найдено» с кнопкой «К каталогу».
- *Чем `push` отличается от `go`?* `push` добавляет экран в стек, `go` строит
  стек заново по адресу.
- *Почему id — строка, а не int?* Так id уже хранятся в моделях FitTrack
  (`ex-01`, `ws-12`); переводить их в число ради маршрута не нужно.
